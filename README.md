# indirect-ili-forecasting
A science fair research project investigating whether indirect Google Trends search signals can improve machine learning forecasts of influenza-like illness (ILI) in the United States and Ohio. Compares search-based models with ILINet-based models and simple forecasting baselines using chronological testing and error metrics.
-------------------------------------------------------------------------------
Predicting influenza-like illness (ILI) is a challenge because the number of cases fluctuates based on the season. ILI surveillance data is reported weekly, so it may not show the most recent activity.  ILINet is the traditional surveillance source used in this project. The outpatient clinics report information about patients with influenza-like symptoms, and are uploaded onto the ILINet database. Because it only updates every week, researchers have investigated faster sources of information. One source, which will be used in this project, is Google Trends. Google Trends provides information about how frequently people search for terms over time.  Previous research has investigated Google Trends for ILI/influenza surveillance (Shih et al. 2024). Google Trends could contain useful information, but in this design it is compared to a model that contains Google Trends and ILINet. The forecasting system will compare three simple baseline approaches with three machine learning approaches to determine which design produces the most accurate next-week ILI predictions. The machine learning approaches will use ILINet data, indirect Google Trends data, or both sources together.
Previous studies have examined searches related to influenza and its symptoms, such as fever and cough. This project investigates whether indirect search signals can also be useful. Indirect search signals are searches that are not directly about influenza but may still be influenced by illness. Examples include searches such as "how to sleep sitting up," "night sweats causes," "best humidifier," or "how to stop shivering." These searches may reflect behaviors associated with illness and could appear before increases in officially reported influenza-like illness data. For example, someone who is sick may search for ways to sleep more comfortably, reduce sweating, stay warm, or make breathing easier without searching for influenza directly. These searches are not necessarily signs of influenza, but changes in their frequency could contain useful information. This project tests whether patterns in these indirect searches can help predict changes in ILI.	
This project uses simple baseline models to establish a basic level of forecasting performance that we compare models to. Baseline comparison is a way to judge whether the more complex machine learning models actually improve forecasting, or if simple forecasting methods are enough. The first baseline model that will be used is the single week baseline. It predicts next week’s ILI value using this week's illness activity, and it does not account for seasonal patterns. Because it is such a simple reference point, it is the simplest possible forecasting approach, so more complex approaches can be judged against it. The next approach is the seasonal baseline. ILI activity tends to follow seasonal patterns. Some parts of the year have higher ILI activity, while some have lower ILI activity. This is different from the single-week baseline because the single-week baseline doesn’t account for that recurring pattern. The seasonal baseline uses historical data for ILI from the same week or time of year, and uses that data to create the prediction for the upcoming week. While the single-week baseline relies on recent or current activity, the seasonal baseline relies on historical seasonal patterns, similar to weather forecasting. The seasonal approach can then be tested against the single-week baseline to determine whether forecasting accuracy improves. The third simple model is the overall-average baseline. It provides another simple benchmark, and its purpose is to see whether machine learning models actually perform better than simply using an average. It calculates the average ILI value from the historical data available to the model, and uses that average as the prediction for next week’s ILI. The prediction stays around the historical average rather than responding to recent changes or seasonal patterns. It is included in this project because it provides a very simple reference point, and gives the six-model comparison another benchmark. These three baselines will be applied to United States ILI data and Ohio ILI data separately. This allows the forecasting approaches to be evaluated at both national and state level. The same three baseline methods are used for both geographic levels, so the comparison would stay consistent. 
	This project will also test three machine learning approaches, with each approach predicting next week’s ILI value. The ILINet-only model uses ILINet/FluView information and historical ILI information to predict the following week’s value. Its purpose is to test how well traditional surveillance performs when used in a machine learning model. It is different from the single-week baseline because it learns relationships from historical data instead of simply copying last week’s value. The second machine learning model is the Google Trends-only model. It uses the selected microbehavioral Google Trends signals, and predicts next week’s ILI using search behavior. It tests whether indirect search behavior contains useful predictive information by itself. The third machine learning approach uses IlINet and indirect Google Trends signals, and tests whether search signals add useful information beyond regular surveillance. An important comparison that results from this is ILINet-only vs. combined model, and to see how the implementation of Google Trends data could improve the model. The three machine learning models will be compared with the three baseline models, and all six approaches will be tested separately for the United States and Ohio 
	But why should Google search data be trusted as a forecasting signal? Google Flu Trends (GFT) was an earlier attempt to use search behavior to predict influenza. GFT used the search activity as a signal for influenza activity. It initially showed promising results, but later it produced significant forecasting errors. GFT’s errors demonstrated the limitations of using search behavior alone.  There are many reasons why search behavior could change, but the general examples are news coverage, public/media attention, general interest, or other factors unrelated to the actual illness. Drawing from these facts, increased searches do not necessarily mean increased influenza activity, and Google search data should therefore be treated as an additional signal, not automatically as a replacement for ILINet. This project does not rely on Google search signals alone, and it compares ILINet-only models with IIINet + indirect Google search signals. This comparison tests whether adding search signals improves forecasting accuracy.
